# Экраны приложения (спринт 3)

Реализованы экраны S1–S4 из прототипа: главная, список дисциплин, журнал оценок и форма
оценки. Экран «Динамика и цель» остаётся на спринт 4–5.

## 1. Навигация

```
Главная (S1)
└── Дисциплины (S2)
    └── Журнал дисциплины (S3)
        └── Форма оценки (S4) — добавление или редактирование
```

Возврат — штатный `finish()`: из формы в журнал, из журнала в список, из списка на главную.
Данные на всех экранах обновляются сами: экраны подписаны на `Flow` из репозитория, а
журнал после сохранения оценки не нужно перезагружать вручную.

## 2. Экран S2 «Дисциплины»

* `DisciplinesActivity` + `DisciplinesViewModel` + `DisciplineAdapter` (ListAdapter + DiffUtil).
* Показывает название, преподавателя, количество оценок и средний балл.
* Дисциплины ниже порога 3,5 помечены меткой «риск» и цветом — но не только цветом.
* Пустое состояние: «Дисциплин пока нет» с пояснением.
* Клик по карточке открывает журнал с `disciplineId` и названием.

## 3. Экран S3 «Журнал дисциплины»

* `JournalActivity` + `JournalViewModel` + `GradeAdapter`.
* Сверху — средний балл и количество оценок, ниже — список записей.
* Каждая запись: дата, вид работы, значение в цветном круге, комментарий.
* Меню записи «···»: «Изменить» и «Удалить». Удаление — только после диалога
  подтверждения с видом работы.
* FAB «+» и кнопка в пустом состоянии открывают форму добавления.
* Пустое состояние: «Оценок пока нет» и кнопка «Добавить оценку».
* После сохранения или удаления средний балл пересчитывается автоматически.

## 4. Экран S4 «Форма оценки»

* `GradeEditActivity` + `GradeEditViewModel`; один экран для добавления и редактирования
  (заголовок меняется, поля заполняются текущей записью).
* Поля: дисциплина (только чтение), оценка (4 кнопки 2–5), дата (`DatePickerDialog`),
  вид работы (чипы: контрольная, практическая, лабораторная, устный ответ, тест, другое),
  комментарий (необязательный).
* Проверка перед сохранением — `GradeFormValidator`:
  * дисциплина обязательна;
  * оценка обязательна и должна быть в диапазоне 2–5;
  * вид работы обязателен.
* Ошибки показываются под соответствующим полем, кнопка сохранения блокируется на время
  записи, после успеха экран закрывается.

## 5. Состояния и сообщения

| Ситуация | Поведение |
|---|---|
| Нет дисциплин | Текст «Дисциплин пока нет» + пояснение |
| Нет оценок | Текст «Оценок пока нет» + кнопка «Добавить оценку» |
| Низкий средний балл | Метка «риск» и цветной бейдж |
| Не выбрана оценка | «Выберите оценку» под блоком кнопок |
| Не выбран вид работы | «Выберите вид работы» под чипами |
| Удаление | Диалог «Удалить оценку?» с описанием записи |
| Сохранение | Кнопка показывает «Сохранение…» и блокируется |

## 6. Архитектура экранов

* Activity только разметка и подписка на состояние; логика — во ViewModel.
* ViewModel получает репозиторий через фабрику, создаётся через `by viewModels { ... }`.
* Состояние — `StateFlow` + `repeatOnLifecycle(STARTED)`: подписка живёт только пока экран
  видим, поворот не теряет данные.
* Список — `ListAdapter` с `DiffUtil`, поэтому перерисовываются только изменённые строки.
* ViewBinding вместо `findViewById` в новых экранах.

## 7. Проверка

| Проверка | Инструмент | Результат |
|---|---|---|
| Валидация формы: пустая оценка, 6, нет вида работы, нет дисциплины, границы 2–5 | `ручные проверки`, 6 тестов | пройдено |
| Формулы среднего и цели | `ручные проверки`, 9 проверок | пройдено |
| Демо-набор | `ручные проверки`, 3 теста | пройдено |
| Полный сценарий на устройстве: открыть дисциплину → добавить → изменить → удалить | ручной прогон на эмуляторе API 37 со скриншотами | пройдено |
| Сохранение данных | инструментальные тесты Room (спринт 2) | пройдено |
