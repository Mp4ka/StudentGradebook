# Слой данных: Room и локальное хранение

Реализовано в спринте 2. Ниже — что именно лежит в проекте, как проверено и какие
решения приняты.

## 1. Состав пакета `data`

```
data/
├── model/                  доменные модели из спринта 1
│   ├── Discipline.kt
│   ├── Grade.kt
│   └── WorkType.kt
├── db/
│   ├── DisciplineEntity.kt     таблица discipline
│   ├── GradeEntity.kt          таблица grade, FK + индекс
│   ├── DisciplineDao.kt        CRUD и Flow-запросы
│   ├── GradeDao.kt             CRUD и Flow-запросы
│   ├── Converters.kt           LocalDate ↔ epochDay, WorkType ↔ String
│   ├── GradebookDatabase.kt    @Database, версия 1, синглтон
│   └── DemoData.kt             5 дисциплин и 25 оценок
└── GradebookRepository.kt      единая точка доступа для UI
```

Схема зависимостей: `MainActivity → GradebookRepository → DAO → RoomDatabase → SQLite`.
Экран не работает с `Cursor` и SQL: он получает `Flow<List<Grade>>` и `Flow<List<Discipline>>`.

## 2. Схема базы

| Таблица | Поле | Тип SQLite | Ограничения |
|---|---|---|---|
| `discipline` | `id` | INTEGER | PK, AUTOINCREMENT |
| | `name` | TEXT | NOT NULL |
| | `teacherName` | TEXT | NULL |
| `grade` | `id` | INTEGER | PK, AUTOINCREMENT |
| | `disciplineId` | INTEGER | NOT NULL, FK → `discipline.id`, ON DELETE CASCADE |
| | `value` | INTEGER | NOT NULL (диапазон проверяется доменной моделью) |
| | `date` | INTEGER | NOT NULL, epochDay |
| | `workType` | TEXT | NOT NULL, имя константы enum |
| | `comment` | TEXT | NULL |

Индекс `index_grade_disciplineId` создаётся Room по `@Index("disciplineId")`.

Сгенерированная схема лежит в `app/schemas/ru.college.gradebook.data.db.GradebookDatabase/1.json`
(`exportSchema = true`): её можно приложить к отчёту и использовать для будущих миграций.

## 3. Конвертеры

| Kotlin | SQLite | Зачем |
|---|---|---|
| `LocalDate` | `INTEGER` (epochDay) | сортировка и сравнение периодов без разбора строк |
| `WorkType` | `TEXT` (имя константы) | подписи остаются в ресурсах, база не зависит от языка |

Если в базе окажется неизвестное имя вида работы, конвертер вернёт `null` вместо
падения: данные не должны ронять приложение.

## 4. DAO

| Метод | Назначение |
|---|---|
| `insert` / `update` / `delete` | базовые операции над сущностью |
| `deleteById(id)` | удаление по ключу (для каскада дисциплины) |
| `observeAll()` | `Flow`-список для экрана |
| `observeByDiscipline(id)` | `Flow`-журнал выбранной дисциплины |
| `getAll()` / `getByDiscipline(id)` | разовые выборки для тестов и расчётов |
| `findById(id)` | одна запись |
| `count()` | количество строк (проверка пустоты и идемпотентность seed) |

Сортировка оценок — `ORDER BY date DESC, id DESC`: новые сверху, при равной дате
выше та, что добавлена позже.

## 5. Репозиторий

| Метод | Поведение |
|---|---|
| `observeDisciplines()` | `Flow<List<Discipline>>`, сортировка по названию |
| `observeGrades(disciplineId)` | `Flow<List<Grade>>` по дисциплине |
| `observeAllGrades()` | `Flow<List<Grade>>` по всем дисциплинам |
| `addDiscipline(name, teacher)` | тримминг, запрет пустого названия |
| `updateDiscipline(discipline)` | изменение названия/преподавателя |
| `deleteDiscipline(id)` | удаление с каскадом оценок |
| `addGrade(...)` | создаёт доменную `Grade` → валидация 2…5 → вставка |
| `updateGrade(grade)` / `deleteGrade(id)` | изменение и удаление оценки |
| `seedDemoDataIfEmpty()` | заполнение демо-набором только для пустой базы |

Проверка диапазона 2…5 живёт в `Grade.init`, поэтому репозиторий не может записать
оценку 6 даже при прямом вызове. Это же поведение проверяет инструментальный тест.

## 6. Демонстрационные данные

5 дисциплин, 25 оценок, сумма 106, средний балл 4,24.

| Дисциплина | Оценок | Сумма | Средний |
|---|---|---|---|
| Математический анализ | 8 | 38 | 4,75 |
| Базы данных | 6 | 26 | 4,33 |
| Физика | 5 | 16 | 3,20 |
| История | 3 | 14 | 4,67 |
| Философия | 3 | 12 | 4,00 |

Набор загружается один раз при первом запуске; повторный запуск не дублирует записи
(проверяется тестом `demoSeedCreatesDocumentedDataAndIsIdempotent`).

## 7. Как проверено

| Проверка | Инструмент | Результат |
|---|---|---|
| CRUD дисциплины и оценки | инструментальный тест, реальный SQLite | пройден |
| Каскадное удаление оценок | инструментальный тест | пройден |
| Сортировка по дате | инструментальный тест | пройден |
| Сохранение после закрытия и повторного открытия базы | инструментальный тест + перезапуск приложения на эмуляторе | пройден |
| Пустая база не даёт средний балл | инструментальный тест | пройден |
| Демо-набор и идемпотентность | инструментальный тест | пройден |
| Оценка вне 2…5 отклоняется | инструментальный тест | пройден |
| Числа демо-набора совпадают с документами | ручные проверки | пройден |
| Формулы среднего и цели | ручные проверки | 9 проверок пройдены |

Итого: 9 проверок и 7 инструментальных на эмуляторе API 37.

## 8. Что осталось на спринт 3

* `ViewModel` для каждого экрана и `StateFlow` вместо прямой подписки из Activity.
* Экраны списка дисциплин и журнала, формы добавления и редактирования.
* Навигация и пустые состояния.
* Проверка ввода на уровне формы (обязательные поля, диапазон).
