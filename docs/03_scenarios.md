# Пользовательские сценарии и критерии приёмки

Сценарии записаны как «актор — предусловие — поток — результат — критерии приёмки».
Критерии проверяемые: по ним QA составляет тест-кейсы, а разработчик принимает работу.

---

## US-01. Просмотр общей сводки

**Актор:** студент. **Предусловие:** приложение запущено, в базе есть дисциплины и оценки.

1. Открыть приложение.
2. Дождаться загрузки главного экрана.
3. Сравнить общий средний балл, количество оценок и сводку по дисциплинам.

**Результат:** студент видит общий средний балл, число оценок и дисциплин, список
дисциплин с их средними баллами.

**Критерии приёмки**

- [ ] Дано 25 оценок по 5 дисциплинам; когда экран загружен; тогда общий средний балл
      равен среднему арифметическому всех оценок и показан с двумя знаками.
- [ ] Количество оценок и дисциплин совпадает с числом записей в базе.
- [ ] Дисциплины ниже порога 3,5 помечены текстовой меткой «риск», а не только цветом.
- [ ] Если оценок нет, вместо числа показано «—» и текст «Оценок пока нет».

## US-02. Просмотр журнала дисциплины

**Актор:** студент. **Предусловие:** есть дисциплина с оценками.

1. Нажать на дисциплину в списке.
2. Просмотреть средний балл и список оценок.
3. Пролистать список, проверить даты, виды работ и комментарии.

**Результат:** открыт журнал дисциплины; средний балл совпадает со значением в списке.

**Критерии приёмки**

- [ ] Заголовок содержит название дисциплины и преподавателя, если он указан.
- [ ] Каждая запись показывает дату, вид работы, значение и комментарий.
- [ ] Средний балл совпадает со средним в списке дисциплин.
- [ ] По умолчанию записи отсортированы по дате от новых к старым.

## US-03. Добавление оценки

**Актор:** студент. **Предусловие:** открыт журнал дисциплины.

1. Нажать FAB «+».
2. Проверить подставленную дисциплину, выбрать оценку, дату и вид работы.
3. При необходимости добавить комментарий.
4. Нажать «Сохранить».

**Результат:** оценка появляется в журнале, средние баллы дисциплины и общий пересчитаны.

**Критерии приёмки**

- [ ] Форма не сохраняется, пока не выбраны дисциплина, оценка и дата; обязательные
      незаполненные поля подсвечены.
- [ ] Значения оценки ограничены 2, 3, 4, 5; ввод другого значения невозможен.
- [ ] После сохранения запись видна в журнале без перезапуска приложения.
- [ ] Средний балл дисциплины и общий средний балл пересчитаны.
- [ ] При отмене форма закрывается, новые записи не появляются.

## US-04. Редактирование и удаление оценки

**Актор:** студент. **Предусловие:** в журнале есть оценка.

1. Открыть меню записи «···» → «Изменить».
2. Изменить значение или дату, сохранить.
3. Открыть меню другой записи → «Удалить».
4. Подтвердить удаление.

**Результат:** изменённая запись обновлена, удалённая исчезла, средние пересчитаны.

**Критерии приёмки**

- [ ] Форма редактирования открыта с заполненными полями текущей записи.
- [ ] После изменения оценка отображается с новыми значениями, средние пересчитаны.
- [ ] Удаление выполняется только после подтверждения; при отказе запись остаётся.
- [ ] Если удалена последняя оценка дисциплины, средний балл «—», а не 0.

## US-05. Фильтрация и сортировка оценок

**Актор:** студент. **Предусловие:** есть оценки разных видов и дат.

1. Открыть журнал дисциплины.
2. Выбрать вид работы «Контрольные».
3. Задать период «октябрь — ноябрь».
4. Переключить сортировку на «по значению».

**Результат:** остаются только подходящие записи; порядок соответствует сортировке.

**Критерии приёмки**

- [ ] Фильтр по виду работы оставляет только записи выбранного вида.
- [ ] Фильтр по периоду не включает записи вне диапазона дат.
- [ ] Пустой результат объясняется текстом «По выбранным условиям оценок нет» и кнопкой
      сброса фильтров.
- [ ] Сортировка по значению упорядочивает записи по убыванию; выбор сохраняется до
      выхода с экрана.

## US-06. Расчёт целевого балла

**Актор:** студент. **Предусловие:** в дисциплине есть оценки, известен желаемый балл.

1. Открыть экран «Динамика и цель».
2. Выбрать дисциплину и задать цель, например 4,40.
3. Прочитать требуемую оценку и пояснение.
4. Проверить недостижимую цель, например 4,60.

**Результат:** приложение показывает нужную оценку и объясняет, достижима ли цель.

**Критерии приёмки**

- [ ] Требуемая оценка = `ceil(цель × (n + 1) − сумма)` и всегда целое число 2…5.
- [ ] Если результат больше 5, приложение пишет, что цель недостижима одной оценкой, и
      не показывает недопустимое значение.
- [ ] Если цель уже достигнута, приложение сообщает об этом вместо требования оценки ниже 2.
- [ ] Для пустого журнала требуемая оценка равна `ceil(цели)`.

## US-07. Просмотр динамики успеваемости

**Актор:** студент. **Предусловие:** есть оценки минимум за два месяца.

1. Открыть экран «Динамика и цель».
2. Просмотреть столбцы среднего балла по месяцам.
3. Сравнить значения, найти месяц с просадкой.

**Результат:** студент видит изменение среднего балла по месяцам.

**Критерии приёмки**

- [ ] Для каждого месяца с оценками показан средний балл с двумя знаками.
- [ ] Месяцы без оценок не рисуются как нулевые и не искажают график.
- [ ] Значения на графике совпадают со средними по журналу.
- [ ] Подписи читаемы при системном размере шрифта до 130 %.
